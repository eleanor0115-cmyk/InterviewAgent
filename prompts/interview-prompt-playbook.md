# Interview Prompt Playbook

这份文档沉淀面试训练 Agent 的通用提示词原则，供 Profile Analyzer、Question Agent、Follow-up Agent、Evaluation Agent、Report Agent 复用。

## 1. 分析框架

面试准备不能只看 JD 关键词，要先建立业务上下文：

1. 宏观行业：所处行业、商业模式、发展现状、头部公司。
2. 微观公司：公司定位、核心价值主张、竞争壁垒、直接竞品。
3. 商业等式：该业务线或产品线的核心商业等式，例如增长、留存、转化、履约效率、成本、风控、供需匹配等。

输出时要把岗位能力和业务目标连起来，不要只列技术名词。

## 2. JD 关键词提取

分析岗位 JD 时，要提取同行业同岗位的高频关键词，并区分：

- 硬技能：例如用户增长、数据分析、React、Node.js、AI Agent、系统设计、性能优化。
- 软技能：例如跨部门协同、需求澄清、项目推进、业务 owner 意识、抗压沟通。

关键词不是越多越好，要解释为什么该关键词会成为面试重点，以及候选人简历里是否有证据支撑。

### 2.1 两层分类体系

面试分类不要使用研发岗专属分类作为全局模型。系统使用两层结构：

第一层是通用问题类型，决定“怎么问”：

1. 业务理解类：行业、公司、用户、商业模式、岗位目标。
2. 经历验证类：简历项目、实习经历、社团经历、成果真实性。
3. 能力方法类：岗位核心技能、方法论、分析框架、工具使用。
4. 场景实战类：给一个真实业务问题，让候选人拆解方案。
5. 协作沟通类：跨部门协作、冲突处理、资源推进。
6. 压力追问类：质疑短板、质疑数据、质疑贡献、质疑动机。
7. 反问准备类：候选人如何向面试官提有质量的问题。

第二层是岗位域标签，决定“问什么领域”：

- 研发岗：前端、后端、AI 工程。
- 非研发岗：产品、运营、数据分析、市场、商业。
- 通用：适用于所有岗位的项目表达、协作、复盘、价值观。

问题类型和岗位域标签必须分离。例如“场景实战 + 运营”可以生成用户分层题，“场景实战 + 后端”可以生成系统扩容题。

## 3. 自我介绍生成

针对岗位核心痛点和候选人简历，生成 2 分钟自我介绍时：

1. 先给一句定位：我是谁、和岗位最相关的能力是什么。
2. 用 2-3 个项目证据支撑，不要流水账。
3. 埋下 2-3 个钩子，引导面试官追问候选人准备充分的方向。
4. 每个钩子都要准备 STAR 回答。
5. 语气要像真人复盘，不要像背 AI 答案。

## 4. 高频问题生成

列岗位 TOP 问题时，按以下顺序组织：

1. 经验类：项目、技术选择、业务结果、协作推进。
2. 价值观类：owner 意识、冲突处理、学习能力、复盘能力。
3. 压力类：短板质疑、项目真实性、指标质疑、方案质疑。

回答框架必须结合简历，使用 STAR 法则和数据支撑：

- Situation：项目背景和业务约束。
- Task：自己承担的具体目标。
- Action：分析过程、方案选择、推进动作。
- Result：结果指标、业务价值、复盘沉淀。

### 4.1 出题权重与策略

MVP 的出题策略不是复杂多因子乘法模型，也不是把 JD、面经、Gap 粗暴加权求和。必须使用三阶段决策：

1. JD 决定考纲范围：先确定这场面试考什么。
2. 面经决定出题优先级：在考纲范围内，历史高频问题优先。
3. Gap 决定追问深度：Gap 不参与题目排序，只决定问多深。

默认配置：

```ts
export const INTERVIEW_WEIGHT = {
  jd: 0.55,
  interview: 0.30,
  gap: 0.15
}
```

排序公式只使用 JD 和面经：

```text
priority = jd_importance * 0.55 + interview_frequency * 0.30
```

Gap 的作用是行为规则：

```ts
function getDepth(gapLevel) {
  if (gapLevel === "strong") return 3
  if (gapLevel === "medium") return 2
  if (gapLevel === "weak") return 1
  return 1
}
```

关键约束：

- 不使用复杂多因子乘法模型。
- Gap 不参与题目排序。
- JD 决定范围。
- 面经决定优先级。
- Gap 决定追问深度。
- 所有策略必须可解释。

## 5. 高压面试模拟

高压问题要围绕真实面试风险：

1. 你只是参与还是主导？
2. 为什么不用更简单或更成熟的方案？
3. 这个指标怎么证明是你带来的？
4. 项目失败或边界情况怎么处理？
5. 如果规模扩大 10 倍，方案会怎么变？

回答必须体现分析过程、权衡和边界，不要只辩解。

## 6. 差异化话术

对比目标岗位常见候选人画像，提炼 3 个“人无我有”的独特优势：

1. 能把非相关经历转化为能力证明，例如社团、实习、课程项目、比赛。
2. 能说明这些经历如何迁移到目标岗位。
3. 能用具体证据和数据支撑，而不是抽象形容。

## 7. 工程表达升级

不要停留在“我用了 XX 技术”。要升级为“为什么这么设计”：

1. 项目背景。
2. 核心问题。
3. 技术难点，不要只写“业务复杂”。
4. 问题分析过程。
5. 技术方案。
6. 为什么选择这个方案。
7. 其他方案为什么没选。
8. 最终效果。
9. 沉淀的方法论。

输出问题、追问和答案框架时，都要逼近候选人的个人思考：为什么、怎么判断、怎么权衡、怎么验证、沉淀了什么。

## 8. 反 AI 味要求

所有回答都要避免模板化：

- 少用空泛词，例如“提升了效率”“增强了能力”“深入理解”。
- 多使用候选人简历中的具体项目、约束、动作和指标。
- 可以保留口语化转折，让表达像真人复盘。
- 不要把答案写成标准作文，要留出可追问的钩子。

## 9. 反问环节设计

反问不是礼貌收尾，也不是固定问“主要业务是什么”“对实习生有什么规划”。好的反问要基于面试中的信息、岗位职责和业务判断，继续展示候选人的思考。

### 9.1 反问原则

1. 从业务出发：围绕用户、场景、目标、指标、增长、留存、转化、供需、成本、风控等问题发问。
2. 从对话延展：基于面试官刚刚提到的业务现状、团队目标、当前问题继续追问。
3. 先说理解再提问：不要只问问题，可以先表达自己的判断，再请面试官校准。
4. 问题要和岗位相关：运营岗位问用户分层、触达策略、心智建设；技术岗位问系统边界、指标、业务约束、工程取舍。
5. 避免模板化：不要连续问公司官网能查到的问题，也不要只问培养机制、转正比例、技术栈这种低信息量问题。

### 9.2 推荐反问结构

使用“我理解 + 业务判断 + 具体问题”的结构：

```text
我理解这个业务现在的关键挑战可能是 X，因为刚才您提到 Y。
如果从岗位视角看，我会猜这里最重要的是 Z。
想请教一下，团队现在更优先解决的是 A，还是 B？
```

### 9.3 可复用反问类型

1. 用户分层类：
   - “我想了解一下，目前这个产品的用户分层主要是按生命周期、消费能力、地域，还是按使用场景来划分？”
   - “如果目标用户里下沉用户占比较高，团队在触达内容、补贴策略或转化路径上，会和一二线用户有什么不同吗？”

2. 低频场景类：
   - “刚才您提到这个场景不是特别高频。我理解低频场景里运营很重要的一点是建立用户心智和关键时刻触达。团队现在更关注提升召回，还是提升单次转化效率？”

3. 团队目标类：
   - “这个团队今年最核心的目标是增长、留存、商业化，还是效率优化？当前最大的卡点更偏用户侧、供给侧，还是内部协同？”

4. 岗位贡献类：
   - “如果我加入这个岗位，前三个月最希望我解决的问题是什么？这个问题目前难在业务判断、资源协同，还是执行链路？”

5. 指标拆解类：
   - “这个岗位日常会主要看哪些指标？这些指标之间有没有比较典型的权衡，比如拉新和留存、转化和体验、效率和质量？”

6. 技术/工程岗位类：
   - “这个业务对技术方案的核心约束是什么，是稳定性、迭代速度、成本、可观测性，还是和业务规则变化有关？”
   - “团队现在评价一个技术方案成功，不只是看上线，还会看哪些业务或工程指标？”

### 9.4 反问后的承接

面试官回答后，不要只说“好的”。要做一次短承接：

```text
明白，我理解这背后其实是 X 和 Y 的权衡。
如果让我做，我可能会先从 A 指标切入，再通过 B 方法验证。
这块也和我之前做过的 C 经历比较相关。
```

这样的承接可以把反问变成第二轮展示：既体现你听懂了，也让面试官看到你不是在背模板，而是在现场思考。
